# Документация по сервису `/pst`

## 1. Назначение сервиса

Страница `/pst` используется для фотофиксации уборки точек `Kaspi Postomat`.

Сервис решает 4 задачи:

1. Определяет местоположение сотрудника.
2. Показывает ближайшие точки и дает выбрать нужную.
3. Позволяет приложить одну или несколько фотографий уборки.
4. Сохраняет результат:
   - фотографии в `Google Drive`,
   - историю уборок в `Google Sheets`,
   - статус уборки и последнюю дату уборки в основном листе объектов.

---

## 2. Общая архитектура

Сервис состоит из двух частей:

### 2.1. Клиентская часть

Файл:

- [app/src/pages/PstPage.tsx](C:/Users/crypt/OneDrive/Документы/IC WebSite 2/app/src/pages/PstPage.tsx)

Клиент отвечает за:

- отображение страницы `/pst`,
- запрос геолокации,
- загрузку базы точек из `pst-locations.json`,
- поиск и выбор точки,
- прикрепление фотографий,
- сжатие фотографий,
- нанесение штампа на фотографию,
- отправку данных в Google Apps Script.

### 2.2. Серверная часть

Файл:

- [scripts/pst-google-sheets-webapp.js](C:/Users/crypt/OneDrive/Документы/IC WebSite 2/scripts/pst-google-sheets-webapp.js)

Google Apps Script отвечает за:

- прием POST-запроса от страницы `/pst`,
- сохранение фотографий в `Google Drive`,
- создание записи в листе `История уборок`,
- обновление основного листа объектов:
  - `Помыли?`
  - `Последняя дата уборки`

## 3. Откуда берутся точки

Список точек хранится в JSON-файле:

- [app/public/pst-locations.json](C:/Users/crypt/OneDrive/Документы/IC WebSite 2/app/public/pst-locations.json)

Каждая точка содержит:

- `id` — `POSTOMAT_ID`
- `city` — город
- `branch` — филиал
- `address` — адрес
- `lat` — широта
- `lng` — долгота
- `category` — категория точки
- `routeText` — описание расположения
- `surfaceType` — тип покрытия
- `installPlace` — комнатный / уличный
- `cellsCount` — количество ячеек
- `comment`
- `hint`

## 4. Как работает пользовательский сценарий

### Шаг 1. Открытие страницы

Пользователь открывает страницу:

- [https://www.ic-group.kz/pst](https://www.ic-group.kz/pst)

### Шаг 2. Геолокация

Страница запрашивает доступ к геолокации через `navigator.geolocation`.

Если доступ разрешен:

- определяется текущая координата пользователя,
- строится карта,
- показываются ближайшие точки в радиусе `300 метров`.

Если доступ не разрешен:

- пользователь все равно может найти точку вручную через поиск.

### Шаг 3. Выбор точки

Пользователь может выбрать точку:

- из списка ближайших,
- с карты,
- через строку поиска.

После выбора появляется карточка выбранной локации.

### Шаг 4. Добавление фото

Пользователь добавляет одну или несколько фотографий.

Для каждой фотографии на клиенте:

1. изображение открывается в `canvas`,
2. сжимается,
3. на него наносится штамп:
   - дата и время,
   - адрес,
   - город.

### Шаг 5. Отправка

После нажатия кнопки отправки на Apps Script уходит JSON-пакет:

- данные локации,
- дата отправки,
- список сжатых фотографий в `base64`.

## 5. Сжатие фотографий

Сжатие происходит на клиенте в:

- [app/src/pages/PstPage.tsx](C:/Users/crypt/OneDrive/Документы/IC WebSite 2/app/src/pages/PstPage.tsx)

Ключевые правила:

- формат результата: `JPEG`,
- максимальный размер файла: `250 КБ`,
- если фото больше лимита, клиент пробует несколько ступеней качества и размера,
- действующая логика сжатия считается рабочей и специально не менялась без необходимости.

Константа:

- `DRIVE_PHOTO_SIZE_LIMIT_BYTES = 250 * 1024`

## 7. Как работает Google Apps Script

Главная точка входа:

- `doPost(event)`

При получении запроса скрипт:

1. берет lock через `LockService`, чтобы не было конфликтов одновременной записи,
2. читает `payload`,
3. проверяет наличие:
   - `location.id`
   - хотя бы одной фотографии,
4. открывает нужную таблицу,
5. находит строку объекта по `POSTOMAT_ID`,
6. сохраняет фотографии в `Google Drive`,
7. добавляет строку в лист `История уборок`,
8. обновляет основной лист объектов.

## 8. Структура хранения в Google Drive

Корневая папка:

- `PST уборки`

Дальше вложенность строится автоматически:

```text
PST уборки
└── Июнь 2026
    └── Южная Столица
        └── 01.06.2026
            ├── 2026-06-01_13-20-15_PST-5374_1.jpg
            ├── 2026-06-01_13-20-15_PST-5374_2.jpg
            └── ...
```

### Логика создания папок

- если папка месяца уже есть — используется она,
- если папка филиала уже есть — используется она,
- если папка даты уже есть — используется она,
- новые папки создаются только при отсутствии.

### Откуда берется название филиала

Название филиала берется не из адреса и не из ручного ввода, а из данных выбранной локации:

- поле `branch`

Именно поэтому все адреса, относящиеся к одному филиалу, падают в один филиальный каталог.

## 9. Как хранится информация в Google Sheets

Используется одна таблица:

- `SPREADSHEET_ID = 1ApfnLS5npNMBW3YYI9_d94yyWwbfv-Bpck_Hozjcl58`

В ней участвуют два листа.

### 9.1. Основной лист объектов

Обычно это лист:

- `Объекты`

Если лист с таким названием не найден, скрипт берет первый лист, который не называется `История уборок`.

Этот лист является справочником постоматов.

В нем обязательно должна быть колонка:

- `POSTOMAT_ID`

Скрипт по этому ID ищет строку нужного объекта.

#### Что скрипт обновляет в этом листе

Скрипт использует или создает 2 колонки:

- `Помыли?`
- `Последняя дата уборки`

##### `Помыли?`

- в колонке ставятся чекбоксы,
- по умолчанию пустые значения переводятся в `false`,
- после успешной отправки по нужной строке ставится `true`.

##### `Последняя дата уборки`

- в строку объекта записывается дата последней успешной отправки,
- формат: `dd.MM.yyyy`

Пример:

| POSTOMAT_ID | Город | Филиал | Адрес | Помыли? | Последняя дата уборки |
|---|---|---|---|---|---|
| 5374 | Алматы | Южная Столица | мкр. Саялы, ул. Аксай, д. 1 | TRUE | 01.06.2026 |

---

### 9.2. Лист `История уборок`

Если лист отсутствует, скрипт создает его автоматически.

Структура заголовков:

| Колонка | Назначение |
|---|---|
| `POSTOMAT_ID` | ID постомата |
| `Город` | Город точки |
| `Филиал` | Филиал точки |
| `Адрес` | Адрес точки |
| `Широта` | Координата из базы |
| `Долгота` | Координата из базы |
| `Категория точки` | Категория из базы |
| `Дата отправки` | Дата уборки |
| `Время` | Время отправки |
| `Ссылки на фотографии в Google Drive` | Кликабельные ссылки на фотографии |

### Как пишется история

Одна отправка = одна строка.

Если пользователь приложил 3 фотографии, то:

- в `Google Drive` сохраняются 3 файла,
- в `История уборок` создается 1 строка,
- в колонке ссылок появляются 3 кликабельные ссылки:
  - `Фото 1`
  - `Фото 2`
  - `Фото 3`

### Важно

История не перезаписывается.

Каждая новая уборка добавляет новую строку. Это позволяет:

- видеть полную хронологию по объекту,
- фильтровать по филиалу,
- фильтровать по дате,
- смотреть все уборки конкретного `POSTOMAT_ID`.

## 10. Как выглядят связи между Drive и Sheets

Система работает так:

1. Пользователь отправляет фотографии.
2. Скрипт сначала сохраняет их в `Google Drive`.
3. После этого скрипт пишет строку в `История уборок`.
4. В эту строку не вставляются сами изображения, а только ссылки на файлы в Drive.
5. Затем скрипт отмечает объект в основном листе:
   - `Помыли? = true`
   - `Последняя дата уборки = дата отправки`

---

## 11. Что считается успешной отправкой

Успешная отправка — это когда Apps Script возвращает:

```json
{
  "ok": true,
  "version": "2026-06-01-history-sheet-v6"
}
```

Это означает, что:

- запрос принят,
- объект найден,
- фото сохранены в Drive,
- история записана,
- статус объекта обновлен.

---

## 12. Что происходит при ошибке

### Если не передан `POSTOMAT_ID`

Скрипт вернет ошибку:

- `POSTOMAT_ID is missing`

### Если не приложено ни одной фотографии

Скрипт вернет ошибку:

- `At least one photo is required`

### Если объект не найден в таблице

Скрипт вернет ошибку:

- `POSTOMAT_ID <id> not found`

### Если фото превышает лимит

Скрипт вернет ошибку:

- `Photo <name> exceeds the 250KB Drive archive limit`

### Если ошибка случилась во время сохранения файлов

Уже созданные файлы этой отправки помечаются как удаленные (`trashed`), чтобы не оставлять мусор.

## 15. Как обновлять URL в клиенте

URL Apps Script используется в:

- [app/src/pages/PstPage.tsx](C:/Users/crypt/OneDrive/Документы/IC WebSite 2/app/src/pages/PstPage.tsx)

По умолчанию он берется так:

Это значит:

- на проде лучше задавать URL через переменную окружения,
- fallback нужен как резерв.

## 18. Краткое резюме

Сервис работает по простой схеме:

1. Сотрудник выбирает точку на `/pst`
2. Добавляет фото уборки
3. Фото сжимаются и получают штамп
4. Фото сохраняются в `Google Drive`
5. В `История уборок` создается строка со всеми данными и ссылками
6. В основном листе объекта ставится:
   - `Помыли? = true`
   - `Последняя дата уборки = дата отправки`

Это и есть текущая рабочая модель сервиса.
